```swift
private func applyProductMode(_ productMode: ProductMode) {
    currentProductMode = productMode
    pendingProductMode = nil

    switch productMode {
    case .standard:
        pipelineEngine.productMode = productMode
        pipelineEngine.updateCloudClient(nil)
        cloudLLMClient = nil
        llmRuntimeManager?.stop()
        updateLLMRuntimeState(.disabled)

    case .superMode:
        pipelineEngine.updateCloudClient(nil)
        cloudLLMClient = nil
        guard let llmRuntimeManager else {
            pipelineEngine.productMode = productMode
            return
        }
        if isReady {
            Task {
                await handleSuperAssetsChanged()
            }
        } else {
            updateLLMRuntimeState(.notStarted)
        }

    case .cloud:
        // D-07: credential gate
        guard credentialStore.get() != nil else {
            Self.logger.warning("Cloud credentials не найдены, остаёмся на текущем режиме")
            return
        }
        // D-05, D-06: lazy creation, пересоздаём каждый раз
        let authService = SberAuthService(
            credentialProvider: { [credentialStore] in credentialStore.get() }
        )
        let httpClient: HTTPClient = trustPolicy?.urlSession ?? URLSession.shared
        let cloudClient = CloudLLMClient(
            authService: authService,
            httpClient: httpClient
        )
        cloudLLMClient = cloudClient
        pipelineEngine.updateCloudClient(cloudClient)
        // D-02 + Pitfall 2: CloudLLMClient также ставится как LLMClient для embedded snippet path
        pipelineEngine.updateLLMClient(cloudClient)
        pipelineEngine.productMode = .cloud
        llmRuntimeManager?.stop()
        updateLLMRuntimeState(.disabled)
    }

    // Обновляем cloudAvailable
    cloudAvailable = credentialStore.get() != nil
}
```

- D-02: updateCloudClient passes to PipelineEngine
- Pitfall 2: updateLLMClient(cloudClient) ALSO called so embedded snippet path uses cloud client

Also: .standard and .superMode cases now clear cloudClient (cleanup on mode switch away from cloud).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CredentialStore -> SberAuthService | Keychain credentials flow to auth service via closure |
| AppState -> PipelineEngine | Cloud client injected from AppState into pipeline |
| Settings persistence -> applyProductMode | Persisted .cloud mode reloaded on restart |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-05 | Elevation of Privilege | applyProductMode(.cloud) credential bypass | mitigate | guard credentialStore.get() != nil at entry. Cloud mode cannot activate without valid Keychain credentials. |
| T-13-06 | Denial of Service | Persisted .cloud with deleted credentials | mitigate | start() checks currentProductMode.isCloud && credentialStore.get() == nil, auto-downgrades to .standard. No dead state on restart. |
| T-13-07 | Information Disclosure | credentialProvider closure captures credentialStore | accept | CredentialStore reads from Keychain on demand. The closure does not cache secrets. SberAuthService refreshes credentials on each token fetch. |
| T-13-08 | Spoofing | trustPolicy nil fallback to URLSession.shared | accept | If SberTrustPolicy fails to init (PEM missing), URLSession.shared is used. This loses certificate pinning but still uses system TLS. Warning logged at init. Acceptable for development; production bundles always have PEM. |
| T-13-09 | Tampering | usesLocalLLM guard audit correctness | mitigate | Exhaustive grep-verified audit of all 10 sites in RESEARCH.md. Tests verify each guard site behavior for .cloud mode. P1, P2, A1 intentionally keep usesLLM. |
