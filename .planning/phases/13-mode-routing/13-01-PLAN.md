Test mock:

final class MockCloudAudioClient: CloudAudioProcessing, @unchecked Sendable {
    private let lock = NSLock()
    var processAudioResult: String?
    var processAudioError: Error?
    private(set) var processAudioCalls: [(audioData: Data, superStyle: SuperTextStyle, hints: NormalizationHints)] = []

    func processAudio(audioData: Data, superStyle: SuperTextStyle, hints: NormalizationHints) async throws -> String {
        lock.lock()
        processAudioCalls.append((audioData, superStyle, hints))

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PipelineEngine -> CloudLLMClient | Audio data crosses from local to cloud API call path |
| ProductMode persistence | UserDefaults stores mode rawValue, loaded on app restart |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Information Disclosure | PipelineEngine.processCloudPath | accept | Audio data sent to cloud is the core feature. User consents in Phase 15 (UI-04). Phase 13 just builds the routing. |
| T-13-02 | Denial of Service | CloudAudioProcessing.processAudio | mitigate | CloudLLMClient already has 30s timeout (Phase 12). processCloudPath checks cancellation before and after the call. |
| T-13-03 | Tampering | ProductMode persistence | accept | UserDefaults is not encrypted but ProductMode is low-sensitivity (standard/super/cloud). No security impact from tampering. |
| T-13-04 | Elevation of Privilege | ProductMode.isCloud bypass | mitigate | Credential check happens in AppState.applyProductMode (Plan 02), not in PipelineEngine. PipelineEngine trusts the mode it receives -- AppState is the gatekeeper. |
</threat_model>
