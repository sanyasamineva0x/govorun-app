Research finding (RESEARCH.md §Open Questions Q1 + Pitfall 2):
  - Cloud production использует audio-in path (`processAudio` через `/files` upload + chat/completions с attachments)
  - Local production использует text-in path (после STT модуля Python worker)
  - Seed dataset — текстовые inputs, нет audio файлов

Three options:

**Option A (recommended by researcher): text-in symmetric**
  - Cloud и local оба получают text user content через /chat/completions
  - Сравнение apples-to-apples: «как LLM нормализует одинаковый текстовый input»
  - Honest для "quality of normalization" question
  - Но не отражает production cloud path (audio-in)

**Option B: audio-in asymmetric**
  - Cloud uploads TTS-generated audio из seed → /files + chat/completions с attachment
  - Local uses seed text directly
  - «Реалистичное product-level сравнение» — cloud делает то же что в prod, local делает то же что в prod
  - Требует TTS dataset generation — НЕ в scope Phase 16 seed, требует создать

**Option C: defer cloud benchmark полностью**
  - Phase 16 — только coverage closure (Plan 1) + infrastructure (Plan 2)
  - Benchmark — Phase 17 когда есть TTS seed ИЛИ when Sanya решит text-in OK для product decision

Researcher's A1 assumption requires validation: «GigaChat-2-Max через /chat/completions поддерживает text-in без attachments». Это smoke test первым делом в Task 2.

**Task 2 и Task 3 runt ONLY если option-a:**
  - option-a → Task 2 (smoke + local + cloud runs) выполняется
  - option-b → Task 2 возвращает "BLOCKED — TTS dataset требует extra work, вне Phase 16 scope"; Plan 4 документирует blocker и закрывает Phase 16 partial
  - option-c → Task 2 скипается (см. resume-signal handling ниже); Plan 4 документирует deferred state
