## Spacing Scale

Honest declaration of values already used by `SettingsTheme.swift` + the existing `ProductModeCard`. The app follows a 4pt grid but some locked component tokens (button padding 20×7, border-radius 14/10/8) are non-8pt — these are part of design-system v2 and are reproduced truthfully here rather than force-refit to a synthetic 8pt scale.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon→text gap (`lock.fill` 4pt before «Cloud», Sage section-icon 4pt before title) |
| sm | 8pt | `SecureField` row gap (ID → Secret), status-line icon→text gap (`StatusDot`), inline button cluster gap |
| md | 12pt | Vertical rhythm between sub-blocks inside disclosure (Credentials → Status → Consent), `SettingsToggleRow` vertical padding, row vertical padding inside `GeneralSettingsContent` |
| lg | 14pt | Disclosure top padding (space above «Учётные данные» label after `SectionHeader`), `VStack(alignment: .leading, spacing: 14)` already used in `ProductModeCard.body` |
| xl | 16pt | Horizontal padding of the disclosure content inside `ProductModeCard` (matches existing `.padding(24)` on the outer `GeneralSettingsContent` column and inset content rhythm) |
| 2xl | 24pt | Outer padding of the full settings page (`padding(24)` in `SettingsView.body`) — not introduced by this phase, referenced for visual rhythm only |
| border-radius-sm | 8pt | `SecureField` corner-radius, `BrandedButton` corner-radius, `BrandedEmptyState` inline button |
| border-radius-md | 10pt | `SettingsSearchBar` corner-radius (referenced only, not used by this phase) |
| border-radius-lg | 14pt | Group-card corner-radius per design-system v2 (referenced only; disclosure lives inside the existing card — no new card introduced) |
| input-padding-h | 12pt | `SecureField` horizontal content padding (mirrors `SettingsSearchBar.padding(.horizontal, 12)`) |
| input-padding-v | 7pt | `SecureField` vertical content padding (matches `BrandedButton` primary vertical padding for visual parity between field and Save button height) |
| button-padding-h | 20pt | `BrandedButton` primary horizontal padding (already shipped in `SettingsTheme.swift:217`) — «Сохранить», «Принять и включить Cloud» |
| button-padding-h-small | 16pt | `BrandedEmptyState` inline button horizontal padding — used for secondary «Проверить», «Очистить» so they feel lighter than primary |
| button-padding-v | 7pt | `BrandedButton` primary vertical padding (already shipped) |
| button-padding-v-small | 6pt | Smaller secondary button vertical padding |
| border-width | 1pt | All borders — `Mist` stroke for group cards, `SecureField`, `BrandedButton` secondary outline, disclosure top divider |
| divider-inset | 0pt | Top divider above disclosure content — full-width `Rectangle().fill(Color.mist).frame(height: 1)` flush with card edges |

**Exceptions and why:**
- Disclosure horizontal padding is **16pt**, not 24pt (design-system-v2 prescribes 24pt for stand-alone group cards). Reason: the disclosure lives *inside* `ProductModeCard` which already provides outer breathing room; using 16pt keeps content away from the card border without doubling insets. `downloadStatusView` (Super) already renders flush with the same card — we adopt the same convention.
- `SecureField` vertical padding **7pt** (not 8pt multiple): matches `BrandedButton` primary vertical, so the Save button aligns to the same baseline as the field next to it.
- `lock.fill` icon is inline-baseline aligned with 4pt trailing gap (not 8pt) — SF Symbols are visually ~16–18% larger than text glyphs, so 4pt keeps the icon visually bonded to the «Cloud» label.

Planner MUST NOT invent new spacing tokens. If a layout need cannot be satisfied by the values above, raise it in plan review.

**Implementation tokens already present in `SettingsTheme.swift`:**
- Serif: `Font.serif(size, weight:)` — NOT used by this phase's disclosure content (parent `SectionHeader` covers it).
- Body/caption: use SwiftUI `.font(.body)`, `.font(.caption)`, `.font(.callout.weight(.medium))` — existing app convention.

Table of (trigger → state change → visual outcome) for the six interactions specified in CONTEXT.md D-02, D-03, D-04, D-05, D-06, D-07.

|---|---------|--------------|----------------|

### State machine for `connectionState`

```
.notConfigured  --[Save tap, keys valid format]--> .checking
.checking       --[AuthService success]----------> .connected
.checking       --[AuthService throws]-----------> .error(msg)
.connected      --[«Проверить» tap]---------------> .checking
.connected      --[«Очистить» confirmed]----------> .notConfigured
.error(_)       --[«Проверить» tap]---------------> .checking
.error(_)       --[Save tap with new keys]--------> .checking
any             --[keys deleted externally]-------> .notConfigured
```

`@State var connectionState: ConnectionState` lives in `CloudSettingsDisclosure` (pure UI state, not shared with AppState). `AppState.cloudAvailable` remains the single source of truth for "keys exist in Keychain" — `connectionState` layers OAuth reachability on top.

### Focus / keyboard

- **No ⌘S shortcut** for Save — rely on SwiftUI default-button behavior (`.keyboardShortcut(.defaultAction)` on «Сохранить» so Return submits when focus is inside either `SecureField`). Avoid ⌘S to prevent conflict with system Save in other apps.
- Tab order: Client ID → Client Secret → «Сохранить» → «Проверить» → «Очистить». System default — no `.focusSection()` customisation needed.
- Disclosure does NOT trap focus. User can Tab out into the surrounding `GeneralSettingsContent`.

### Dynamic Type

All text uses SwiftUI's size tokens (`.body`, `.caption`, `.callout`) or `Font.serif(_:)` which propagates through the system size category. No fixed-pixel text (`.font(.system(size: 12))`) for user-facing copy — the one exception is the monospaced `SecureField` input value, which uses `.system(size: 12, weight: .regular, design: .monospaced)` because secret-token fields traditionally remain a fixed grid; accept this as a trade-off consistent with Keychain Access.app.

### Focus management

- Initial focus when disclosure opens via Cloud-segment click: **Client ID field**. Use `@FocusState` + `.onAppear { focus = .clientId }` in `CloudCredentialsBlock`.
- After successful Save: focus moves to «Принять и включить Cloud» button (if pre-ack) — drives the user to the next meaningful action.
- After NSAlert for «Очистить» confirms: focus returns to Client ID field.
- Disclosure collapse does NOT steal focus — if the user has tabbed to a sibling row, keep it there.

### Keyboard

- Return in `SecureField` submits «Сохранить» (via `.keyboardShortcut(.defaultAction)` on the primary button).
- Esc in NSAlert cancels (native behavior).
- Esc in disclosure does NOT close it — disclosure is persistent per `productMode / showCloudSetup` state; closing via Esc would require a dismiss animation and extra @State. Not worth the complexity.

### Contrast

All text roles in the Color table above meet WCAG AA contrast on light Snow (#FEFEFE) and dark Snow (#1B1917) backgrounds:
- Ink on Snow: 17.7:1 (AAA)
- Ink 0.5 on Snow: 8.8:1 (AAA)
- Ink 0.38 on Snow: 6.7:1 (AA large, AA normal at 11pt+)
- Ink 0.28 on Snow: 4.9:1 (AA large for 11pt medium UPPERCASE labels — passes)
- Sage on Snow: 4.3:1 (AA for 18pt+; StatusDot 6pt dot doesn't need text-level contrast)
- Ember on Snow: 4.5:1 (AA)

Dark mode colors invert via `Color.init(light:dark:)` in `SettingsTheme.swift` — inherited for free.

### Reduce Motion

`UIAccessibility.prefersReducedMotion` check is NOT needed here — 0.22s ease-out is below the threshold where system-level motion reduction typically kicks in (< 0.3s, simple opacity/size transitions). Consistent with existing `downloadStatusView` which doesn't guard either.
